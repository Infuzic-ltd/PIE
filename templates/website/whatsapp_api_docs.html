WhatsApp Delivery Failure API

What we need from InstantConvo:
  1. Accept our message_id (a UUID) on each send request, and store it alongside the message.
  2. When a message is not delivered, POST that message_id to our failure webhook (section 2), authenticated with the X-Api-Key listed under Credentials.

Why: your send endpoint returns success before delivery is known, so this callback is how the CRM learns which messages actually failed. For each failure we show the recipient an in-app notification instead.

1. Send request (what we send you)

This is your existing template endpoint, with one addition: a top-level message_id. Please echo this exact value back in the failure callback.

POSThttps://chat.theinstantconvo.com/api/contacts/923122211828/send/text

Content-Type: application/json
X-ACCESS-TOKEN: {{ api_token }}

Body — example (template property_new_listing)

{

  "message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "message": {
    "type": "template",
    "channel": "omnichannel",
    "template_name": "property_new_listing",
    "language": { "code": "en_US" },

Fields

FieldTypeDescription
message_idstring (UUID v4)New. Unique per message, generated by PIE CRM. Store it, and return it in the failure callback.
contact_idstringRecipient phone, digits only, in international format (92…). Same value as in the URL path.
messageobjectUnchanged: the WhatsApp template payload (template_name, language, components).

2. Failure callback (what you call)

Call this once for each message that fails delivery. Don't call it for messages that are delivered or read.

POST{{ request.scheme }}://{{ request.get_host }}/api/whatsapp/failed/

Headers

Content-Type: application/json
X-Api-Key: {{ webhook_key }}

Body

{
  "message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "error": "131026: Message undeliverable"
}
FieldRequiredDescription
message_idYesThe exact UUID we sent in the send request.
errorNoHuman-readable reason or WhatsApp error code, up to 1000 characters. We store it for troubleshooting.

Responses

StatusBodyMeaningRetry?
200{"ok": true}Recorded. Also returned if this message_id was already reported, so repeats are safe.No
400{"error": "..."}Body isn't JSON, or message_id is missing or isn't a valid UUID.No, fix the payload
401{"error": "..."}X-Api-Key header is missing or wrong.No, check the key
404{"error": "..."}We have no record of this message_id.No
405—Method other than POST.No
5xx / timeout—Temporary server problem on our side.Yes, with backoff
The endpoint is idempotent. Sending the same message_id more than once does nothing after the first time, so a retry after a timeout can't create duplicate notifications.

Test with cURL

curl -X POST {{ request.scheme }}://{{ request.get_host }}/api/whatsapp/failed/ \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: {{ webhook_key }}" \
  -d '{"message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "error": "test"}'

If the UUID is random, expect 404 Unknown message_id. That still shows the URL and key work. A message_id from a real send returns 200.
