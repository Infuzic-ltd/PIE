WhatsApp Delivery Failure Webhook

When a WhatsApp message from PIE CRM fails to deliver, POST its message_id to this endpoint.

That's all this API does. For each failure we show the recipient an in-app notification in the CRM instead.

Quick reference

ItemValue
URL{{ request.scheme }}://{{ request.get_host }}/api/whatsapp/failed/
MethodPOST
Auth headerX-Api-Key: 99326155-4fb1-4f6d-8bb3-215405cfc8f2
Content-Typeapplication/json
When to callOnce for each message that is not delivered. Don't call it for sent, delivered or read messages.

Where message_id comes from

Every send request PIE CRM makes to your /api/contacts/{contact_id}/send/text endpoint includes a top-level message_id (UUID). Store it with the message, and send the same value back here if delivery fails.

{
  "contact_id": "923122211828",
  "message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",   ← send this back
  "message": { ...template payload, unchanged... }
}

Request

Headers

Content-Type: application/json
X-Api-Key: 99326155-4fb1-4f6d-8bb3-215405cfc8f2

Body

{
  "message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "error": "131026: Message undeliverable"
}
FieldTypeRequiredDescription
message_idstring (UUID)YesThe exact message_id from our send request.
errorstringNoFailure reason or WhatsApp error code, up to 1000 characters.

Responses

StatusBodyMeaningRetry?
200{"ok": true}Recorded. Also returned if this message_id was already reported.No
400{"error": "..."}Body isn't valid JSON, or message_id is missing or isn't a UUID.No, fix the body
401{"error": "..."}X-Api-Key header is missing or wrong.No, fix the header
404{"error": "..."}We have no message with this message_id.No
405—A method other than POST was used.No
5xx / timeout—Temporary problem on our side.Yes, with backoff
Reporting the same message_id more than once is safe. Only the first call has any effect, so retrying after a timeout never creates duplicate notifications.

Example

curl -X POST {{ request.scheme }}://{{ request.get_host }}/api/whatsapp/failed/ \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: 99326155-4fb1-4f6d-8bb3-215405cfc8f2" \
  -d '{"message_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "error": "test"}'

A made-up UUID like the one above returns 404, which still confirms the URL and key are correct. A message_id from a real send returns 200.
