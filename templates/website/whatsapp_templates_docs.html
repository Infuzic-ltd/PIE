WhatsApp Business API — Template Submission Plan

PIE Real Estate needs 5 message templates

Four cover the inventory-change alert (grouped by shape, not by event, so one wording pattern reuses across similar changes) and one covers the lead property recommendation. This is a greenfield build — the CRM has no WhatsApp Business API integration today, only a client-side wa.me share link, so nothing here reuses an existing template convention.

Scope → grouped by shape Lead template category → Utility Language → English only

At a glance

All five submit under Meta’s current three-category system (Utility / Marketing / Authentication). Every template here is Utility — the agent/affiliate alerts because they report on an operational change to inventory the recipient already manages, and the lead template because it is scoped to reply to an inbound inquiry (see the compliance note in its card below).

Inventory alerts — agents & affiliates

All four share one shape: a header naming the property, a body carrying only what changed (previous value → new value) plus a timestamp, and an optional button back into the CRM. Status labels are passed in as plain text, not hard-coded in the template, so new statuses (e.g. adding “On Hold” or “Withdrawn” to the Property model — see Implementation notes) don’t require a template resubmission.

Utility is only the compliant category while this is sent as a reply to a lead’s own inbound inquiry, and only to leads who’ve opted in to WhatsApp messages. If it starts going out proactively — e.g. an automated “new listings this week” blast to leads who haven’t asked — that content is Marketing under Meta’s policy and needs its own template in that category; sending promotional content under a Utility template risks template suspension.

Implementation notes

Not part of the Meta submission, but worth flagging before build:

The Property model’s STATUS_CHOICES currently only has Active / Inactive / Sold — “On Hold” and “Withdrawn” aren’t stored states yet. The templates above take status as free text, so no resubmission is needed once those states are added, but the status-change logic itself still needs to be built.
Price history isn’t currently tracked (only narrative activity-log text) — capturing the previous price at the moment of change will need a small model change to populate property_price_change accurately.
Swap your-pie-domain.com in every button URL for the CRM’s real production domain before submitting. Each WhatsApp template is also sent one recipient at a time via the Cloud API — fanning a single event out to every relevant agent/affiliate is orchestration this document doesn’t cover.
