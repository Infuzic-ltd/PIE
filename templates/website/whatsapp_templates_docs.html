WhatsApp Business API — Template Submission Plan

PIE Real Estate needs 10 message templates

Four cover the inventory-change alert, one covers the lead property recommendation, and five new ones extend WhatsApp across the rest of the CRM’s existing pipeline — lead reminders, internal FYI alerts, financial figures, client-facing milestones, and affiliate onboarding. Every group is grouped by shape, not by event, so one wording pattern reuses across several distinct triggers. Document-expiry and affiliate-commission notifications are deliberately excluded — both need a new field added to the data model first (see Implementation notes).

Scope → grouped by shape Lead-facing templates → Utility Language → English only Tier 3 (needs new fields) → skipped

At a glance

All ten submit under Meta’s current three-category system (Utility / Marketing / Authentication) and every one here is Utility. The inventory and internal templates report on an operational change the recipient already manages; the two client-facing templates are scoped to a reply to that specific lead’s own inquiry or an update on their own active deal (see the compliance notes in those cards).

Inventory alerts — agents & affiliates

All four share one shape: a header naming the property, a body carrying only what changed (previous value → new value) plus a timestamp, and an optional button back into the CRM. Status labels are passed in as plain text, not hard-coded in the template, so new statuses (e.g. adding “On Hold” or “Withdrawn” to the Property model — see Implementation notes) don’t require a template resubmission.

Implementation notes

Not part of the Meta submission, but worth flagging before build:

The Property model’s STATUS_CHOICES currently only has Active / Inactive / Sold — “On Hold” and “Withdrawn” aren’t stored states yet. The templates above take status as free text, so no resubmission is needed once those states are added, but the status-change logic itself still needs to be built.
Price history isn’t currently tracked (only narrative activity-log text) — capturing the previous price at the moment of change will need a small model change to populate property_price_change accurately.
Lead.follow_up_date and Lead.visit_scheduled_at are stored today but nothing reads them back — the reminder and visit-reminder triggers in lead_reminder_alert need a new scheduled job (daily for follow-ups, hourly or T-1-day for visits), not just a hook on an existing view. Agent Target Pace needs a similar new weekly job.
LeadPayment creation (lead_add_payment) and locking deal financials (lead_set_deal_financials) currently call zero notification code at all — wiring WhatsApp here means adding the first-ever notification hook to both views, in-app included.
Swap your-pie-domain.com in every button URL for the CRM’s real production domain before submitting. Each WhatsApp template is also sent one recipient at a time via the Cloud API — fanning a single event out to every relevant agent/affiliate/lead is orchestration this document doesn’t cover.
Skipped on purpose: document-expiry reminders (PropertyDocument has no expiry/valid-until field today) and affiliate commission-earned alerts (no commission field exists anywhere on the affiliate relationship). Add the underlying field to the data model first, then template these.
